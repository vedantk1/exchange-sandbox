# v0.1.0 — Spot Exchange Simulator

The initial release is a self-hostable spot-exchange simulator for inspecting trading, exact accounting and recovery. It includes trader and administrator workspaces, an isolated reviewer demo, and a Docker Compose deployment with HTTPS. All funds and executions are virtual. There is no hosted demo, custody, external price feed or connection to a real exchange.

## Try it

Use Node.js 24 and pnpm 10.22.0 from a normal, non-root account:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm portfolio:serve
```

Two isolated Chromium windows open as the trader and administrator. The trader starts with a real partial fill; inspect it, cancel the remainder, and review the released balances and retained history. Use the administrator window to pause trading, inspect simulator inventory and start ongoing synthetic activity. Close either window or press Ctrl+C to remove the disposable installation. Nothing is added to the persistent development database. On Linux, `pnpm exec playwright install --with-deps chromium` installs browser system dependencies when needed.

For automatic reviewer-flow validation, run `pnpm portfolio:serve --headless --smoke`. For persistent self-hosting, follow the [Compose guide](../RELEASE.md#self-host-package); it requires Docker Compose, private generated configuration and interactive administrator setup.

## Included

- Price/time-priority limit matching, partial fills and cancellation, plus protected market orders with a fixed 5% price guard and 10-second preview expiry.
- Integer financial amounts, exact fees, reservations and a double-entry journal. Matching, accounting and command receipts commit together in PostgreSQL so retries can recover the original outcome.
- Invitation-only authentication, credential rotation/recovery, audited administrator controls and the finite-inventory two-account market simulator.
- Live order/balance/history views, internal execution candles with exact UTC data, session rollover with exactly-once allocations, read-only financial archives, complete paginated history and coherent scoped CSV exports.
- Bounded database work and shutdown, immutable accepted order terms, migration checksums, a frozen historical upgrade fixture, restricted runtime database access and private operational diagnostics.
- Reproducible self-host verification, cleanup and restore tooling. Regression coverage includes process loss, uncertain replies, permissions, exact accounting and real Chromium flows.

## Validation and limits

Run `pnpm check` for type checking, formatting, unit/integration/browser tests and the web build. The release guide records [packaged HTTPS acceptance](../RELEASE.md#fresh-compose-acceptance), [bounded repeated startup checks](../RELEASE.md#bounded-startup-checks), and the source revisions and scope of retained evidence. Inspect the release commit's GitHub Actions result when evaluating it.

The clean-source local candidate `9a3545a` passed five fresh full Compose/HTTPS journeys, with 19 checks and four cleanup confirmations per run; the [sanitized report](../evidence/reviewer-startup-checks-result.json) retains their source/image identities. Local validation also passed 228 unit tests, 226 PostgreSQL tests, 29 Chromium scenarios and the clean-source reviewer install/smoke. These are local results; the final release revision must also pass its published CI run.

A focused Linux reproduction captured Chromium aborting the initial login POST with `net::ERR_NETWORK_CHANGED` during fresh installation setup. Acceptance now waits for stable Linux interface/address state before launching Chromium, within a fixed deadline and without retrying login requests. The [release guide](../RELEASE.md#bounded-startup-checks) records the diagnosis, source evidence and limits. Application authentication and TLS verification are unchanged. The final green CI run and reviewed sanitized startup report are retained with the published release.

The recorded performance exercises are short, disclosed workloads. They do not establish sustained capacity under the packaged API's 512 MiB/one-CPU limit. Chromium is the automated browser target; cross-browser certification is not claimed. Exports reject oversized bundles explicitly. Real-money operation and regulatory readiness are outside scope.
